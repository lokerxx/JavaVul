# shiro-1.25_1.42 操作教程

- 类型：单体靶场
- 目录：`shiro-1.25_1.42`
- 端口：`9969`
- 推荐入口：`/shiro-1.25_1.42`

## 这是什么

Shiro Padding Oracle 靶场

## 启动前准备

1. 在仓库根目录执行 `bash run-local-build.sh`。
2. 等待对应容器启动完成，并确认端口 `9969` 已经监听。
3. 如果你还想通过首页统一发包，再额外确认 `http://宿主机IP:5000/` 能打开。

## 方式一：通过首页测试

1. 打开 `http://宿主机IP:5000/`。
2. 在搜索框输入 `shiro_1_25_1_42、padding oracle、oracle` 过滤到当前项目。
3. 先点“测试”发送内置模板。
4. 推荐先跑 `shiro_1_25_1_42_normal` 登录拿 Cookie，再用“重放数据包”把攻击请求里的 `Cookie` 头改成真实值。
5. 再跑 `shiro_1_25_1_42_attack`，重点看响应头里是否出现 `rememberMe=deleteMe`。

推荐直接使用的首页条目：
- `shiro_1_25_1_42_attack`：GET http://宿主机IP:9969/home.jsp
- `shiro_1_25_1_42_normal`：POST http://宿主机IP:9969/login.jsp

## 方式二：直接访问接口测试

1. 先访问推荐入口：`http://宿主机IP:9969/shiro-1.25_1.42`。
2. 先执行正常登录请求：`curl -i -X POST "http://宿主机IP:9969/login.jsp" -H "Content-Type: application/x-www-form-urlencoded" -d "username=root&password=secret&rememberMe=true"`。
3. 从响应头里复制 `Set-Cookie` 返回的 `rememberMe` 值。
4. 带合法 Cookie 请求受保护资源：`curl -i "http://宿主机IP:9969/home.jsp" -H "Cookie: rememberMe=把上一步拿到的合法Cookie填这里"`。
5. 再带畸形 Cookie 请求同一个资源：`curl -i "http://宿主机IP:9969/home.jsp" -H "Cookie: rememberMe=QUFB"`。
6. 辅助信息接口：`curl "http://宿主机IP:9969/oracle/info"`。

## 测试时重点看什么

1. 先看正常登录时是否成功回写 `rememberMe` Cookie。
2. 再看访问 `/home.jsp` 时，响应头里是否出现 `Set-Cookie: rememberMe=deleteMe`。
3. 如果你修改了 Cookie，重点对比“合法 Cookie”和“畸形 Cookie”下的状态码、跳转位置、页面内容和响应头差异。
